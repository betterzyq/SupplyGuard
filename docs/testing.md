# 测试与证据规范

## 分层验证
| 层级 | 目标 | 隔离方式 |
|---|---|---|
| 单元 | 权限、金额、引用、时间、算法边界 | 无数据库、无 LLM、固定数据 |
| API 契约 | 认证、响应、非法参数、管理边界 | FastAPI 依赖覆盖；管理 API 用假会话，禁止写业务数据 |
| 本机集成 | 真登录、权限刷新、演示数据、代理 | 专用 8100/3100；仅登录审计与增量演示账号会写库 |
| 浏览器 | 导航、角色入口、错误提示、布局、筛选 | 专用前端产物目录，固定视口及场景 |
| 阶段回归 | 已通过能力不退化 | 仅新增变更或失败时扩大测试 |

P1 不需要付费模型调用、Embedding、GPU、数据库重置或压力测试。健康检查不作为经营首页数据依赖。

## P1 必测
- admin、enterprise、全部旧内部岗位归一；空/未知/旧供应商账号无业务权限。
- 同租户共享文档；跨租户永远拒绝，包括 admin；Qdrant 过滤与文档策略一致。
- 企业用户可使用全部业务图查询、上传及业务工具，不能运行基准和访问完整审计。
- 旧供应商账号不能借旧 token 继续访问；前端刷新服务端角色，账号切换清理查询缓存。
- 演示订单引用有效，ID 唯一，坐标有效，金额精确，按唯一订单计算敞口；无模型结果时明确显示尚未训练。
- 首页无外部 AI 调用；非法场景返回 404，不伪造空数据成功；未认证返回 401。
- 关闭验收服务不影响原有 3000/8000 或基础设施；停止前校验进程身份。

## P2—P6 专项
- 地图：筛选、重叠节点、窄屏、WebGL 失败提示、离线字体/底图、轨迹不越过播放时点。
- 仿真：无需求、无替代、环路、重复路径、库存可覆盖、容量不足、多事件相关性、措施成本非负。
- 模型：成熟标签、时间切分、同单聚合、所有预处理仅在训练集拟合、阈值只在验证集选择。
- 业务：持久化、重启、幂等导入、错误行不落库、并发更新、CSV/Excel 导出与租户隔离。
- 性能：固定设备/规模/并发，报告地图首屏、帧率和 API P95。P2 目标 1,000 站点/2,000 路线可交互，P6 依据实测记录最终上限，不宣称未测能力。

## 证据
机器产物：`.local/acceptance/phase-N/`；可提交的摘要：`docs/reports/phase-N.md`。记录日期/时区、代码版本及工作区差异、命令、退出码、测试数、服务地址、已知问题。日志不含密码、密钥或 token。

测试通过不等同于用户人工验收通过。报告必须分别记录“开发自测”和“用户验收”。

## P2 已实现的专项入口

- `make phase2-check`：P1 的 43 项回归与 P2 的 35 项专项，包含时区/未来事件、轨迹裁切、ETA 获知时间、金额筛选一致性、BOM 路径、无效演示数据拒绝、认证/租户上下文和资源哈希；另做 lint、类型与生产构建。
- `make phase2-smoke`：真实登录，通过前端代理检查三场景、轨迹、筛选、批次详情、认证错误和本地资源；20 次串行热请求记录 API P50/P95，不能当作并发 SLA。
- `make phase2-browser`：检查实际画布尺寸与海陆/路线像素，避免“初始化成功但地图不可见”的假阳性；真实鼠标点击聚合与站点、事件→批次→有连线的订单依赖图、跨页筛选和时间、分享链接、1366/1920 视口、断网刷新、缓存边界、WebGL 降级、退出清理与固定规模负载。保留截图与录像。
- 软件 WebGL 的 render 事件频率仅描述该次 CPU 绘制，JS heap 不代表浏览器总内存。首图时间包含页内导航与数据/字体初始化；不包含用户电脑到服务器的网络或 SSH 隧道时间。

## P3 专项入口

- `make phase3-check`：P1/P2 回归与 P3 手算、库存守恒、多级 BOM/重复路径、产能、零需求、部分恢复、共享资源、运输批次防重复、不可行措施、认证、跨用户/租户快照、时区与输入重放；另做 lint、类型与隔离生产构建。
- `make phase3-smoke`：真实 HTTP 复核 100/20 的三天/七天案例、4500/1140 成本、三个制造场景、快照幂等与无认证/未认证措施拒绝。
- `make phase3-browser`：地图事件进入、修改参数提示过期、手算、图表逐日核对、增库存、零需求、组合措施、加急/改道、场景切换及 JSON 下载，包含两个视口与无外部请求检查。
- `make phase3-snapshot-check`：按真实账号读取最近 smoke 快照，和先前完整 JSON 的 SHA256 比较；验收服务重启后再次执行，验证本项目文件保存。跨身份拒绝在 API 测试覆盖。
- 仿真算法与界面都不把延期订单金额当作实际损失或节省收益。边界与失败案例属于交付，不靠删除历史结果制造改善。

## P4 已实现的专项入口

- `make phase4-data-check`：原始数据官方大小与SHA256；下载是独立显式`phase4-data`命令，日常检查不安装依赖、不调外部模型。
- `make phase4-check`：P1—P3共125项回归+P4的27项，覆盖时间可用性、禁止holdout标签进入特征、同一时刻无前视、完整路径/精确引用/NA、真实权限与租户查询、缺失模型/非法域/私有模型下载拒绝；有界构建/类型检查。
- `make phase4-reproduce`：单独不可覆盖实验，验证协议、源码、切分、选型、阈值和全部模型概率；不重新按测试指标选型。
- `make phase4-audit`：公开基准逐单时间与哈希、真实模型样例、契约和当前active复现证据；不把缺失复现视为成功。
- `make phase4-smoke`、`make phase4-browser`：专用服务真实登录，验证概率/下载一致、两类角色、制造域拒绝、误报规模/金额取舍、双视口、无运行时外部资源。
- 本阶段实测结果与边界见[报告](reports/phase-4.md)。离线评分契约通过不是在线RAG质量；公开零售预测不是制造迁移效果。

## P5 已实现的专项入口

- `make phase5-check`：独立PostgreSQL迁移升级/降级/再升级，P1—P4回归与P5真实事务API测试；含幂等、并发版本冲突、跨租户复合外键、错误行整批回滚、私有快照主动共享、报告字节/哈希/过期、公式拒绝与本地订阅。另做有界生产构建、类型、lint。
- `make phase5-smoke`：本机真实登录/导入/任务/报告/游标/OpenAPI；创建明确模拟来源的验收数据，不执行外部业务。
- `make phase5-browser`：风险→任务→验证完成、中文映射、坏坐标、XLSX模板与报告、刷新保留、双角色协作、双视口、无外部运行请求。
- `scripts/phase5_smoke.py --verify-saved`：重启后读取最近smoke保存的对象/任务/报告。
- `make phase5-audit`：项目迁移、备份哈希、真实隔离恢复、复合引用、业务审计、报告字节与浏览器/重启证据。
- 不在现有项目库做降级/重建，不升级全局库或使用GPU；保留既有P3个人文件与P4固定实验。具体结果见[P5报告](reports/phase-5.md)。

## P6 最终验证

`make phase6-check`重跑173项P1—P5测试、真实独立PostgreSQL迁移/事务、生产构建、类型和lint。`make phase6-smoke`对三个制造故事执行真实仿真/共享/任务/审计/报告哈希，另外每接口1次预热+20次串行采样；不作压测或SLA。`make phase6-browser`检查新导览、故事跳转、视图重置、商业假设下载/负值/输入错误/零分母、503降级及恢复。`make phase6-regression`顺序跑P1—P5浏览器，P2记录地图与1000站点/2000路线几何负载，P5追加明确模拟QA记录。

P6性能固定CPU软件WebGL、视口与演示数据规模，报告原始样本/统计口径；API采样与浏览器回归顺序进行，不同时运行。API/Web内存只读取核验归属的父进程，不扫其他项目进程、不统计其负载。共享宿主机仍有抖动，容量/并发/长期运行未验证。

`phase4-audit`和`phase5-audit`核对既有模型/业务证据；`phase6_release.py`封存当前源码，`phase6-audit`核对清单、部署指纹、P5产物与库备份及前端密钥检查。所有证据在`.local/acceptance/phase-6/`；最终总体通过仍需用户P6-H1—H13人审。
