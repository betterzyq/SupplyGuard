# P1：产品基础与两类角色

## 需求
实现 BIZ-01、AUTH-01、DATA-01 和 NFR-01。交付清晰的产品入口与可信数据基础；新地图不属于本阶段。

## 开发
1. 生效角色归一至 admin/enterprise；旧内部岗位映射 enterprise；旧供应商和未知角色拒绝。业务文档和图查询同租户共享，管理端只允许 admin。
2. 登录页与侧栏使用业务语言，开发诊断放管理员二级入口。Header 展示企业工作区/角色，去掉常驻 LLM 型号与频繁健康探测。
3. 经营首页显示统一演示域的风险敞口、待处置订单、事件和场景；显示来源、时点和版本，指标可展开解释和核算。
4. JSON 契约包含供应商、站点、物料、产品、订单、批次和三个场景，后端校验后返回。此数据不混入旧 PG/Neo4j 的 5 供应商演示。
5. 新增 `GET /api/v1/business/overview?scenario_id=...`、`GET /api/v1/business/scenarios`；认证但不依赖外部 AI。
6. 增量准备两类演示账号；不调用原破坏性 seed。修复审计列表缺少租户过滤的问题。
7. 提供自测、隔离启动/关闭、真实 HTTP 验收入口；隔离 Next.js 输出目录，不覆盖已有 `.next`。

## 测试
离线权限/租户/API/金额/契约测试；修改文件 lint；TypeScript；前端生产构建；本机真登录与管理边界；可用时执行浏览器交互并留证。只使用专属环境和限额 CPU。
