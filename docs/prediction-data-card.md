# P4 数据卡与获取审计

本阶段使用公开历史零售订单验证“下单时能否提前识别后续运输延误”，不是制造企业供应商停产、灾害或库存缺料的真实预测。制造业务继续使用明确标注的合成数据与约束仿真。

## 粒度、目标与队列

- 原始 180,519 个订单行、65,752 笔订单；行 ID 无重复。同笔订单的时间与标签一致。订单是切分、训练、排名与指标的单位。
- 排除包含 CANCELED / SUSPECTED_FRAUD 行的整笔订单，共 2,855 单；这些状态的 4,423 个订单行解释了全部“实际天数>计划天数”和原标签不一致的记录。
- 其余目标是订单内任一行 `Days for shipping (real) > Days for shipment (scheduled)`，并核对 `Late_delivery_risk`；额外标签冲突、无效时间、负天数或重复行会拒绝/排除并计数，不能默默改标签。本次额外无效订单为 0。
- 不将取消视作准时交付。本任务不训练延误天数回归，因此不报告无对应任务的 MAE。
- 保留了其他状态的公开运输标签；状态列不用于预测。部分记录仍标记 PENDING / PROCESSING，实际天数与发运时间的真实性、事件到达顺序无法独立核实。**队列筛选使用结果状态，不能将此次指标直接视为全量新订单上线效果。**
- “shipping date” 是发运字段，不是可验证签收时间。任务名称按公开运输延误标签解释，不能宣称已验证真实送达 ETA。

## 字段可用时间与泄漏边界

| 字段组 | 处理与可用性假设 |
|---|---|
| 下单日期的月/星期/小时、运输方式、计划天数 | 假定下单时已知；原始数据没有订单变更历史，无法证明后续从未被修改 |
| 订单行数量、数量、单价、折扣、产品/类别、市场/地区/国家 | 假定订单创建时可得；金额用数量×单价×(1-折扣)重算，未使用实现销售/利润；原币种未注明，不换算人民币 |
| 历史产品延误率/观察数量 | 仅使用训练订单、且标签可用时间严格早于当前预测时间；验证/测试固定为训练截止时可知状态 |
| 图结构度数 | 产品—市场、类别—产品的历史共现结构；仅较早训练订单形成边，同一时刻互不可见；不是供应商地理图或原始供应链因果关系 |
| 实际天数、发运时间、原延误标签、订单状态 | 仅用于目标、队列和成熟时间审计，禁止进入模型矩阵 |
| 交付状态、利润、实际销售、客户汇总/标识、邮箱/姓名/地址/密码 | 不读取为预测特征 |
| 经纬度 | 审计越界数为 0；不作为模型特征，不把客户坐标当供应商站点 |

源数据日期没有提供可核实的时区，实验按原始无时区记录排序，不宣称这些日期是北京时间或UTC。

标签可用时间采用 `max(发运时间, 下单时间+实际运输天数)+7天` 的保守代理。7 天是预先固定的观察延迟假设，不是源数据提供的入库时间。它能约束本实验的时间计算，不能替代真实 ERP/物流事件时钟。
