# P3 仿真方法与接口口径

## 数据来源和边界

`data/demo/simulation-v1.json` 是制造演示的独立合成排产扩展，引用 P1 的物料、产品、站点及 10 个未交付/未取消订单；不修改 P1/P2 数据文件。新增数量、BOM 用量、库存、产能、到货与费用均是假设，不是接入 ERP 后的真实值。当前引擎版本 `daily-stock-flow-3.0.0`。

这是按日推进的确定性计划模型。相同用户、相同版本和输入产生相同结果及 SHA256 编号；没有随机收益、训练模型、LLM 数字计算或统计置信区间。未完成订单的延误只给观测下界，上界未知。

## 每日计算顺序

1. 常规计划到货：逐物料、逐供给通道，以当天计划量乘以来源/途经站点的最小可用比例。受扰期使用输入比例；恢复期第 k 天为 `r + (1-r) × k/(R+1)`，k=1…R，之后恢复 100%。重叠事件取最小值，不相加或相乘。到货数量向下保留 4 位小数。
2. 措施按执行日安排。替代采购按日供给，调拨是一次性有限库存；提前期后到货。来源/途经站点在执行日受阻会减少实际安排数量。窗口内无法到货的新增采购/调拨标为 outside_window、不执行且不收费，不当作免费库存。
3. 在途批次与常规日到货独立。到货日后路径未完全恢复则整批等待；加急和改道只重排原批次，不能凭空增加到货。加急保留原约束路径，改道使用目录中的备援路径。同批次两种运输措施冲突会拒绝。
4. 日初入库后释放生产需求，按承诺日、订单 ID 排产。某订单当天最大生产量为 `min(已释放未生产数量, 订单日产能, floor(各物料可用库存 / 单产品 BOM 用量))`。先完成的订单消耗库存，后续订单不能重复使用；积压可在后续产能内补产。
5. 记录期初、常规/在途/措施入库、消耗和结余；满足 `期初 + 三类入库 - 消耗 = 结余 >= 0`。订单完整生产后视为交付可用，当前未模拟成品运输时间。

共享可用库存池是明确的简化：目前不区分工厂的库存所有权、跨厂调拨、生产换线和小时内先后顺序，也不是约束最优解。物料可以有多级装配 BOM；展开时合并同一叶物料的数量，拒绝环路、未知节点、重复子项和小于 0.0001 物料单位精度的展开用量。证据路径最多显示 32 条，数值计算仍使用完整聚合。

需求规模影响订单数量和每日释放需求，向上取整数件；生产能力不随需求扩大。0% 需求对应零件数，库存缓冲显示不适用。

## 指标与证据

| 指标 | 定义 |
|---|---|
| P1 规则敞口 | 原 P1 最新演示时点的规则关联金额，保留原口径，不替换首页数值 |
| 拓扑暴露金额 | 当前事件关联供给站点/通道→物料→BOM→订单的唯一订单金额，不考虑库存 |
| 仿真延期订单金额 | 承诺日已进入窗口且截至该日未完成的唯一订单完整金额；不是损失，不按物料路径重复累计 |
| 首次缺料日 | 期末清空已释放生产积压所需的某物料数量超过该物料结余的首日；D1 对应输入 as_of 所在日 |
| 物料净缺口 | `max(0, 已释放生产积压的该物料用量 - 期末库存)`；每物料独立报告，不把不同物料单位混加 |
| 峰值缺口 | 每物料在窗口内每日净缺口的最大值，不重复累加跨日积压 |
| 初始库存缓冲 | 初始库存 / 窗口内峰值计划日需求；保留两位小数，不含后续到货；零需求为 null |
| 延期区间 | 已完成订单给确定天数；未完成订单给 `[已观测下界, null]`，null 表示上界未知 |
| 窗口外待判断 | 承诺日在窗口外且窗口内仍未完成；不能直接断言延期。已提前完成和零需求订单不计入该类 |

阻塞证据包含物料、发生日、关联供给约束事件、供给站点与途经路径、BOM 和订单。事件关联描述供给约束，不冒充统计因果归因。没有物料阻塞但延期时，需检查需求释放、日产能和承诺日；结果另列产能受限日。

## 措施与费用

服务器从固定目录读取认证状态、供货上限、备援库存、提前期与费用，客户端不能提交覆盖这些约束。未认证、负/零数量、负费用、超产能/库存、重复措施、重复使用同批次、共享资源超额均拒绝。可在同一方案组合措施；方案之间是独立反事实，不共享或重复消耗彼此的库存。

费用为实际安排的数量 × 增量单价 + 每项措施一次性固定费用，逐账单四舍五入到分。替代采购按安排日逐天计量；调拨一次计量；运输按原整批数量计量，即使受阻后未改善结果也收取已安排的费用。没有把基础采购款、税费、延误罚款或企业利润编造进来。

“延期订单金额减少”和“措施成本”分别呈现，前者不是节省收益，不自动相减生成净收益或 ROI。库存增加可以保护特定瓶颈，但复杂多物料计划采用固定排产规则，不能宣称所有局部增加都会实现全局最优。

## 手算基准

港口场景选择“手算样例”：库存 100、日需 20、日到货 20、单订单 200 件、D1 起连续释放 10 天、D10 承诺、日产能 40、BOM 1:1。默认 14 天窗口。

- 停供 3 天：D1/D2/D3 结余 80/60/40；D4 恢复日到货 20，因此无缺料，D10 完成。
- 停供 7 天：D5 结余 0，D6 缺口 20，D7 缺口 40；恢复后逐步补足，D12 完成，延期 2 天。
- 替代采购：20 件/日 × 7 天，提前期 1 天，增量 25 元/件 + 固定 1000 元，成本 `20×7×25+1000=4500` 元；本例不再延期。
- 调拨：80 件，提前期 1 天，8 元/件 + 固定 500 元，成本 `80×8+500=1140` 元；本例不再延期。
- 同方案组合两项，成本 5640 元；重复路径仍只计算一个订单金额 1,280,000 元。

## API 与快照

| 接口 | 行为 |
|---|---|
| GET `/api/v1/simulation/templates` | scenario_id、preset_id、at_time、event_id；返回受信任输入、目录和默认方案 |
| POST `/api/v1/simulation/run` | 运行一个输入及可选措施，保存完整输入与结果 |
| POST `/api/v1/simulation/comparison` | simulation（无措施基线）+ 1—3 个 plans；每方案最多 6 项措施 |
| GET `/api/v1/simulation/runs/{64位SHA256}` | 读取当前租户且当前用户的运行或比较快照；其他租户/用户返回 404 |

POST 输入支持 horizon_days（1—30）、demand_percent（0—300）、event_ids、event_overrides、material_overrides、supply_overrides、inbound_overrides 和 measures；明细契约见 `packages/business/simulation_models.py` 和当前 OpenAPI。运输与调拨 duration_days 必须为 1；运输 quantity 为 1，含义为执行原整批。

公开样例标为 source_type=synthetic。当前场景尚未发现的事件不能通过显式 ID 提前引入。不存在的场景/快照 404、无认证 401、旧供应商账号 403、无效或不可行输入 422。企业用户和管理员均可模拟，但管理员不能跨租户或读取别人的个人快照。

输入快照包含完整模板、覆盖后的数值、事件/措施、数据与引擎版本；运行编号还绑定 tenant/user。结果以权限 0600 的原子文件保存在 `.local/simulation-runs/<tenant>/<user>/`，不会进入公共地图缓存，也不迁移或重置业务数据库。这是单机仿真工作区保存，非正式报告系统或企业任务持久化；后者在 P5 实现。页面提供 JSON 下载，服务重启后可以通过上述 GET 接口恢复同一内容。
