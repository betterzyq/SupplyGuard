# 产品需求基线 v2

## 1. 定位与客户
面向制造企业的供应链风险预测与韧性决策平台。首个演示行业为电子/装备制造，围绕关键物料和交付履约。目标使用者包括采购、物流、计划、质量、供应链管理及企业管理层；这些岗位共享 enterprise 角色，岗位仅用于任务分工与数据标签。

产品路径：发现异常 → 判断影响 → 比较措施 → 执行与复盘。企业控制台为主要使用入口，逐步提供风险评分、影响分析和事件订阅 API。首版不承诺真实 ERP、承运商、AIS 或付费风险源已接入。

## 2. 权限（替代旧岗位 RBAC）
| 能力 | enterprise | admin |
|---|---|---|
| 本企业经营总览、风险、地图、物流、模拟、供应商、订单 | 允许 | 允许 |
| 本企业文档上传、检索、业务问答及业务报告 | 允许 | 允许 |
| 本企业处置任务与复盘 | 允许 | 允许 |
| 基准运行、开发诊断、系统配置、完整审计日志 | 禁止 | 允许 |
| 其他租户数据 | 禁止 | 禁止 |
| 他人的个人会话/偏好 | 禁止 | 仅保留现有本租户管理能力，不扩大范围 |

- 生效角色仅 `admin`、`enterprise`。旧采购、物流、财务、质量、管理层角色兼容归一为 enterprise；有 admin 则归一为 admin。
- 旧 external_supplier、未知角色及无角色账号不自动升级为企业用户；拒绝登录和业务 API，供应商门户退出当前产品范围。
- 保留历史数据库角色和文档权限字段用于兼容与回滚；本租户企业成员不再受部门、岗位、旧密级或白名单限制。上传页面明确“本企业共享”。
- 普通查询和本地业务报告不设置逐项角色审批。未来采购下单、外发通知等产生真实外部效果的操作，另行定义业务确认，不混入当前只读演示。
- 角色从数据库重建，不依赖 token 内旧角色声明。现有登录会话通过 `/auth/me` 刷新角色。
- 旧权限基准结果仅作历史记录，须标明策略版本，不能用于证明新策略效果。

## 4. 数据与指标
- 金额按人民币元存储，明确币种；未来多币种必须提供汇率日期，不可直接混加。
- 风险敞口金额 = 当前条件下被标记为有风险的唯一订单金额之和；同一订单只计算一次。它不是预计损失，也不是已经发生的损失。
- 待处置高风险订单 = 风险等级 high/critical 且未处置完成的唯一订单数。
- 缺料缓冲 = 可用库存 / 正的日需求（天）；零需求显示不适用，不作除零或无穷大营销指标。
- 预警提前量 = 首次有效预警至实际异常的时间，仅历史回放可测；没有标签则不展示伪造提升。
- 模拟改善 = 相同场景及约束下，基线与措施方案的差值；必须注明仿真结果。
- 概率、规则分数、事件严重程度和业务金额分别呈现，不能混用。
- 统一对象：Supplier、Site、Material、BOM、Product、Customer、Order、Shipment、Route、Milestone、RiskEvent、Scenario；后续追加 Prediction、Simulation、Action、ImportBatch。
- 每套演示数据有 `schema_version`、`dataset_version`、`source_type=synthetic`、`as_of`。首页统一从后端数据计算，不在组件中硬编码不同口径的数字。
- 订单关联产品、供应商、批次；产品依赖物料；风险关联站点、供应商及明确的订单。P1 建立最小数据基础，P2/P3 扩展轨迹和库存计算。

## 5. 地图交互
- 真实站点定位，物料和订单通过站点关联，不伪造唯一坐标。
- 供应依赖、计划路线、历史轨迹和风险传播使用不同图例。插值位置标记为模拟位置。
- 默认 2D 地图，支持缩放、平移、选中、聚合与详情；图谱用于解释业务依赖。
- 同一筛选和时钟控制地图、列表与指标。模拟播放不得提前露出未来轨迹。
- 核心演示资源离线可用；底图授权、署名、字体及样式都需检查。

## 6. 预测与评测
- 首任务：下单时预测是否晚于承诺日期；取消订单单独处理，未成熟标签不能作已知真值。
- 首选候选：DataCo、Olist；SupplyGraph 作为图规划研究扩展。下载后先审计许可、字段与质量，暂不承诺全集适用。
- 同一订单不跨集合，按时间切分，历史特征仅用当时已知信息，保留锁定测试集。
- 比较历史延误率、规则、逻辑回归、CatBoost/LightGBM；图特征做消融；GNN 为可选扩展。
- 主报 PR-AUC、Precision/Recall、Recall@K、校准、MAE（有回归任务时），不以 Accuracy 单独排名。
- 传播基准与真实预测基准分开；仿真数据不能证明真实灾害传播精度。收益比较须包含按订单金额排序的基线。
- 每次运行记录数据哈希、版本、切分、参数、随机种子、耗时和失败样例；无样本指标显示 N/A。

## 7. 商业验证与范围
订阅可按供应商/站点规模、功能和部署方式设计，API 是平台扩展能力。竞赛展示三类场景：港口拥堵、二级供应商停产、区域灾害。市场规模和投资回报使用显式假设，客户访谈/试点数据另行验证。

本轮不要求真实 ERP、付费情报源、全球 AIS、大规模 GNN、真实采购执行和完整计费。不得将未交付页面包装为已实现能力。
